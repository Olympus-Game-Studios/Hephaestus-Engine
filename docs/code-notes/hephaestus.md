# Hephaestus code notes

## Shared engine library migration

- `CMakeLists.txt:HephaestusGame` — `LUA_AVAILABLE` follows `LUA_FOUND` for every target, so `LuaScriptEngine.h` compiles the same way in the editor, the game and the shared runtime library. `HEPHAESTUS_GAME_SCRIPTING` only controls whether `engine/Game/GameMain.cpp:main` starts the Lua engine; when it is OFF the game still links Lua and ships its DLL (the package stager already requires `lua54.dll`).
- `engine/Gfx/EngineFrameRenderer.cpp:EngineFrameRenderer::recordBillboards` — light billboard icons (and their ID-buffer pass) are derived from `LightComponent::type` at draw time. The former `EditorIconComponent` was attached by a `Scene` constructor hook compiled only outside `HEPHAESTUS_GAME_RUNTIME`, which made `Scene` behave differently per host; it was never serialized, so removing it changes no saved data.
- `engine/Gfx/EngineFrameRenderer.h:EngineFrameRenderer::Init` — `editorOverlays` replaces the former `HEPHAESTUS_GAME_RUNTIME` compile-time branches, which changed the class layout per host (an ODR hazard once one library serves both). The editor (`QtEditorEngine`) passes `true`; `GameMain` passes `false`, so grid, debug overlay, outlines, ID picker, gizmos and billboards are never created in packaged games. Every `record*`/`cleanup*` path checks its own `initialized` flag, and `recordGrid` now checks `m_editorGrid.initialized` as well.
- `CMakeLists.txt:HephaestusRuntime` — the Qt-free engine as one static library with PUBLIC includes, links and `LUA_AVAILABLE`. `HephaestusGame` keeps only `GameMain.cpp`/`RuntimeBootstrap.cpp` and links it. Editor services (`EditorContext`, `PlayModeManager`, `EditorAssetPipeline`, `ReimportManager`, `FileWatcher`, `RecoveryStore`, `OpenDocumentRegistry`, `AssetOperationService`, `DerivedDataCache`, `EditorViewState`, `EditorCameraController`) were dropped from the game: nothing in the runtime includes them, and the game still links. Never add Qt to this target.
- `CMakeLists.txt:HephaestusPluginCore` — owns `engine/Assets/AssetPathPolicy.cpp` and `AssetReferenceIndex.cpp` next to `AssetMountRegistry.cpp`. They were compiled in both `HephaestusBuildCore` and the game; one owner avoids duplicate definitions once the editor links the runtime library and `BuildCore` together.
- `CMakeLists.txt:HephaestusEditorCore` — Qt-free editor services and documents (`EditorContext`, `PlayModeManager`, asset pipeline/reimport/recovery, `EditorDocument`, `MaterialEditor/*`, inspector selection and clipboard). Links `HephaestusRuntime` PUBLIC. `HephaestusEngine` now compiles only `engine/Core/main.cpp` plus the Qt sources and gets the engine, Lua, Vulkan, Jolt and include paths through this library. The unused `EDITOR_ONLY_SOURCES` list was removed.
- `CMakeLists.txt` test targets — 35 test executables link `HephaestusRuntime` (or `HephaestusEditorCore` when they cover editor services) instead of recompiling engine sources, so tests exercise the same objects and `LUA_AVAILABLE` value the hosts ship. Some tests that previously compiled `LuaScriptEngine` without `LUA_AVAILABLE` (the stub) now run against real Lua.
- `engine/Gfx/EngineFrameRenderer.cpp:EngineFrameRenderer::AddStaticMesh` — the one static-mesh upload, used by `GameMain` and `QtEditorEngine::uploadMeshToGPU`. It keeps the game's device-local staged upload (the editor previously used host-visible buffers; no code maps static mesh buffers after upload). `GameMain` registers the raw scene `meshAssetPath` as an alias because `sourceKey` is now `sourcePath.generic_string()`.
- `engine/Scripting/ScriptPhysicsBindings.cpp:MakeScriptPhysicsBinding` / `MakeScriptCharacterBinding` — the one implementation of the Lua `Physics.*` and `Character.*` callbacks, formerly copied in `GameMain.cpp` and `QtEditorEngine::StartPlayMode`. Hosts pass a `ScriptPhysicsAccessor` that is called on every script call: `GameMain` returns its fixed scene and systems; the editor returns null physics members unless `m_physicsInitialized` is set, so a physics restart in Play never leaves scripts holding stale pointers. Covered by `engine/Tests/PhysicsLuaTests.cpp`.
- `engine/Core/SimulationStep.cpp:RunSimulationStep` — the one gameplay frame order for Editor Play (realtime and `StepFrames`) and `GameMain`: audio sources, `PrepareSceneBodies`, C++ `UpdateScripts`, Lua `Update`, safe point, physics `Update` + contact dispatch, safe point, `CharacterAnimationSystem::Tick`, animation-finished + Lua `LateUpdate`, safe point, C++ `LateUpdateScripts`, safe point. `reloadAtSafePoint` processes a pending reload and ends the frame (returns `false`). `onPhysicsError` keeps the editor's existing behaviour (log, set `m_physicsInitialized = false`, skip physics for the rest of the frame); the game leaves it unset so physics exceptions still propagate. See the physics exceptions note under FPS blocker fixes. `PlayModeManager::Tick`/`StepTick` (no callers) and `BeginScriptFrame`/`FinishScriptFrame` were replaced by `PlayModeManager::AdvanceFrameTime`. Covered by `engine/Tests/SimulationStepTests.cpp`.
- `engine/Game/GameMain.cpp:main` — the packaged game now owns a C++ `ScriptEngine` (initialized after scene load, `AwakeScripts` at start and after a scene reload, `DestroyScripts` before reload, `Shutdown` at exit) and passes it to `RunSimulationStep`, matching Editor Play. Nothing attaches C++ scripts in packaged builds yet, so this has no visible effect until C++ scripting gains an attachment path.
- `engine/Gfx/BuiltinMeshes.cpp:AddBuiltinMeshes` — the one generator for `builtin://cube` (1x1x1), `builtin://plane`, `builtin://sphere` (radius 0.5) and `builtin://skinned_rest_fixture`, used by `QtEditorEngine::createBuiltinMeshes` and `GameMain`. Packaged games previously drew the cube and sphere at twice the editor size (half-extent 1.0, matching `.engine/meshes/Cube.obj`) while colliders authored in the editor use 0.5 extents. `GameMain`'s fallback that maps a missing `.engine/meshes/<Name>` file to `builtin://<name>` now logs a warning, because the builtin can differ in size from the missing file.

## FPS blocker fixes

- `Plugins/HephaestusFPS/Content/Scripts/FPS/Logic.lua:Logic.tickFire` — while a weapon cannot fire (reloading, empty, or an automatic trigger released) `nextFire` is held at no less than `now`. Before, `now` kept advancing and the next held frame paid back the gap as up to 4 shots in one frame (a 10 rps weapon re-pressed after 0.25 s fired 2). Catch-up still applies to a hitch while the trigger stays held. Covered by `engine/Tests/FPSLogicTests.cpp` (re-press after idle, fire after a held reload).
- `engine/Plugins/PluginContent.cpp:FindMissingEnabledPlugins` / `engine/Build/PackageStager.cpp:PackageStager::stage` — ids set `true` in `.hephaestus/plugins.json` with no manifest under `<engineRoot>/Plugins` or `<projectRoot>/Plugins` fail the package with `PACKAGE_PLUGIN_NOT_FOUND`, naming both folders. `CollectEnabledPluginContent` skips unknown ids, so a wrong engine root (`RuntimeLocator::discoverEngineRoot` falls back to the executable folder) used to produce a package without the FPS plugin's `Content`. Covered by `engine/Tests/PackageLayoutTests.cpp`.
- `engine/Physics/JoltPhysicsSystem.cpp:JoltPhysicsSystem::ApplyRenderInterpolation` / `RestoreSimulationPoses` — `Update` records each live character controller's position and each dynamic body's local position and Euler rotation before the last substep (`CaptureInterpolationStart`) and after it (`CaptureInterpolationEnd`). Hosts call `ApplyRenderInterpolation` after the simulation step and before camera sync and render (`engine/Game/GameMain.cpp:main` in realtime mode, `QtEditorEngine` tick while playing in realtime with physics up) and `RestoreSimulationPoses` straight after render, so scripts, automation and the next step only ever see stepped poses. The blend factor is `m_Accumulator / kPhysicsFixedDt`, so rendering trails the simulation by up to one step. An entity whose transform no longer equals the recorded stepped pose (teleport, script write) is skipped. Character rotation is excluded because scripts set facing every frame. Rotation blends per Euler component and is skipped when any component moves more than 90 degrees in a step. Covered by `engine/Tests/JoltPhysicsIntegrationTests.cpp` and `engine/Tests/CharacterControllerJoltTests.cpp`.
- `engine/Core/SimulationStep.cpp:RunSimulationStep` (physics exceptions) — every call reachable from `PrepareSceneBodies`, `JoltPhysicsSystem::Update`, `CharacterControllerSystem::FixedStep` and Lua contact dispatch was checked for throwing operations. `engine/Physics` has no `throw` outside `JoltPhysicsEngine::Initialize`. Mesh loading through `ModelImporter::LoadModel` catches its own parse errors. Filesystem calls use `std::error_code` overloads except `fs::current_path()`. Lua callbacks run under `lua_pcall`. A project root and mesh path outside the ANSI code page were tried in a scratch integration test, and nothing threw. Only allocation failure and `fs::current_path()` remain, so no physics exception source was found to fix, and the packaged game still lets one propagate to the crash handler. The editor's `onPhysicsError` was added during early Jolt integration with no recorded failure behind it.
- `engine/Physics/PhysicsWorldPose.h:PoseQuatToEulerXYZ` — extracts Euler angles for `q = qx * qy * qz` (the `R = Rx * Ry * Rz` order of `TransformComponent::GetLocalMatrix`, `SetFromMatrix` and `PoseQuatFromEulerXYZ`). It previously used the Z-Y-X formula, so `SyncTransformFromPhysics` and `TryComposeWorldPose` wrote the wrong rotation for any dynamic body turned about more than one axis (`(0.3, 0.4, 0.5)` came back as `(0.46, 0.19, 0.61)`). The unused, equally wrong `QuatToEulerXYZ` in `engine/Physics/JoltPhysicsSystem.cpp` was removed. Covered by `engine/Tests/PhysicsFoundationTests.cpp` (round trip and agreement with `SetFromMatrix`).

## Probe GI Phase 0: HDR scene target and tone mapping

- `engine/Gfx/VulkanSwapchain.cpp:VulkanSwapchain::initInternal` — the swapchain render pass has two subpasses. `kSceneSubpass` renders skybox and lit meshes into `hdrImage` (`R16G16B16A16_SFLOAT`) with the shared depth buffer. `kOverlaySubpass` reads `hdrImage` as an input attachment, tone-maps into the swapchain image, then draws grid, debug overlay, billboards, light gizmos, outlines, the transform gizmo and HUI against the same depth. The swapchain attachment uses `LOAD_OP_DONT_CARE` because the tone-map pass writes every pixel. One HDR image serves every frame in flight, so the external dependency into `kSceneSubpass` waits for the previous frame's colour/depth writes and fragment-shader input reads. The old dependency had `srcAccessMask = 0`, which ordered the shared depth image only by execution.
- `engine/Gfx/VulkanSwapchain.cpp:ChooseSurfaceFormat` — replaces `formats[0]`. It prefers `B8G8R8A8_UNORM`, then `R8G8B8A8_UNORM`, then the `_SRGB` variants, all with `SRGB_NONLINEAR`. Otherwise it keeps the first entry, and a lone `UNDEFINED` entry maps to `B8G8R8A8_UNORM`. Before, a driver that listed an `_SRGB` format first got gamma applied twice, because the shaders already applied `pow(1/2.2)`. Covered by `engine/Tests/SwapchainFormatTests.cpp`.
- `shaders/tonemap.frag` / `engine/Gfx/EngineFrameRenderer.cpp:EngineFrameRenderer::recordToneMap` — the only place that applies Reinhard and `pow(1/2.2)`. `triangle.frag` (lit and unlit) and `skybox.frag` now write linear HDR. The output matches the previous per-shader curve. On an `_SRGB` swapchain the shader decodes with the exact sRGB EOTF so the hardware encode lands on the same display value. Translucent materials now blend in linear HDR before tone mapping instead of after it, so overlapping translucent surfaces can look slightly different. Opaque output is unchanged: sampled sky, wall and floor pixels in the packaged FPS `Redline` scene were identical before and after.
- `engine/Gfx/EngineFrameRenderer.cpp:DisplayToSceneLinear` — `FrameRenderConfig::clearColor*` is a display colour, so the HDR clear value is its inverse tone map (capped at 0.999 before the Reinhard inverse), and the background looks the same as before.
- `engine/Gfx/EngineFrameRenderer.cpp:EngineFrameRenderer::createToneMapResources` — created in `Init` and on every swapchain recreation (it binds `hdrImageView`). A failure is fatal, as for `createPipeline`, because nothing else writes the swapchain image. Every pipeline built against `m_swapchain->renderPass` must pick its subpass. Scene pipelines (`VulkanPipeline::Init`, `createSkinnedMainPipelines`, `Skybox::CreatePipeline`) keep subpass 0. Overlay pipelines use `VulkanSwapchain::kOverlaySubpass`, and `VulkanHUIRenderer::Init`/`OnSwapchainRecreated` take it as a parameter.
- `engine/Gfx/EngineFrameRenderer.cpp:EngineFrameRenderer::prepareEnvironment` — the HDRI reload and `updateEnvironmentReflectionDescriptor` now run in `RenderFrame` before `vkBeginCommandBuffer`. They used to run inside `recordMainPass`, after the editor `recordIdPass` had already bound `m_descriptorSets[imageIndex]`. Writing binding 5 of a bound set, or destroying the old HDRI it pointed at, invalidated the command buffer every editor frame (validation: `VUID-*-commandBuffer-recording`, "destroy or updated without UPDATE_AFTER_BIND"). The packaged game has no ID pass, so it was not affected. `findEnvironment` is the shared Environment lookup used by both paths. Material texture slots were already deferred to `flushPendingTextureDescriptorUpdates` for the same reason.

## Probe GI Phase 1: sky irradiance

- `engine/Gfx/SkyIrradiance.cpp:ProjectEquirectIrradianceSH` — projects the HDRI to order-2 SH and pre-multiplies the clamped-cosine band factors, so `EvaluateIrradianceSH` (and `triangle.frag:evaluateSkyIrradiance`, which uses the same basis constants) returns irradiance. Texel directions match `triangle.frag:sampleEnvironmentReflection` for bottom-up rows (`VulkanTexture::LoadHDRFromFile` flips on load). It runs on the CPU in `EngineFrameRenderer::Skybox::LoadHDRI` from the pixels `LoadHDRFromFile` now hands back, so no GPU compute is needed yet; compute arrives with probe relighting in Phase 4. Covered by `engine/Tests/SkyIrradianceTests.cpp`.
- Sun exclusion (Andrew's decision, 2026-10-28): texels within 5 degrees of the brightest texel are skipped, because the scene's directional light already supplies the sun with shadows. In `studio_garden_1k.hdr` the sun reaches radiance ~1.1e5 and carries ~90% of the irradiance. Kept in, it double-counts the sun, and SH9 ringing drove faces turned away from it to zero (negative before the clamp). The result matches a clamp of the sun pixels within 0.03 on every axis. For an HDRI without a sun, this removes only one 5 degree cap (under 1% of the sphere). An HDRI scene with no directional light therefore gets no sun.
- `engine/Gfx/EngineFrameRenderer.cpp:EngineFrameRenderer::updateLightingUBO` — when the Environment HDRI is loaded and `useAsIBL` is set (the same condition as HDRI reflections), `environmentReflectionParams.z = 1`, `.w = hdriIntensity`, and `skyIrradianceSH[9]` is appended to `LightingUBO` after `cascadeSplits`. `triangle.frag` then uses `E(N) / pi * albedo * (1 - metallic) * ao` for ambient. Otherwise it keeps the old flat ambient, so scenes without an HDRI look the same as before. Scenes with an HDRI change look: shadowed faces now take the sky's colour and brightness.

## Probe GI Phase 2: probe volume component

- `engine/Scene/Components.h:ProbeVolumeComponent` — an axis-aligned grid centred on the entity's world translation. Entity rotation and scale are ignored, because DDGI probe grids are axis-aligned. `ProbeOffset` spreads `probeCount` probes from one face to the other on each axis, and a single probe on an axis sits at the centre. The editor overlay uses it now, and the Phase 3 bake and Phase 4 GPU layout must use the same formula. No bake-file path is stored yet; Phase 3 adds it together with the bake. Covered by `engine/Tests/ProbeVolumeTests.cpp`.
- `engine/Scene/SceneSerializer.cpp:WriteProbeVolumeJson` / `ApplyProbeVolumeJson` — written by both `Serialize` and `SerializeToString` and read by `Deserialize`, as `"ProbeVolume": { enabled, size, probeCounts: [x, y, z], intensity }`. Counts below 1 load as 1. Scenes without the key load unchanged.
- Like `EnvironmentComponent`, it is a scene-level lighting object. It is not in `PrefabComponentIO::SupportedTypes` or the automation `ComponentMetadataRegistry`, so `engine/UI/InspectorSelectionModel.cpp:BatchAddComponent` / `BatchRemoveComponent` and `EditorMainWindow` reset handle it directly, as they do Environment.
- `engine/UI/QtEditor/ProbeVolumeInspector.cpp` — enabled, size, probe counts (1-64 per axis), intensity, and a read-only total probe count, using the shared mixed-value helpers for multi-selection.
- `engine/UI/QtEditor/QtEditorEngine.cpp:AppendProbeVolumeDebugDraw` — draws each volume's box and a cross at every probe through the existing editor debug overlay (cyan when enabled, grey when disabled). The overlay is drawn only in the editor while not playing. It draws every probe, so a 64x64x64 volume uploads about 1.5M overlay vertices a frame. The packaged game loads the component but does not use it yet.

## Probe GI Phase 3: probe bake

- `engine/Gfx/ProbeBake.cpp:BakeProbeVolume` — CPU ray tracing on a median-split BVH, not the GPU cube capture the design page described. Hits are exact, it needs no new render passes, and it is unit-testable without a GPU. Each probe traces `kProbeBakeRaysPerProbe` (128) fixed spherical-Fibonacci directions (`ProbeRayDirection`; the Phase 4 GPU relight must use the same directions) and stores distance, oriented normal, material albedo and emissive per ray, or distance < 0 for sky. Probes are split across `std::thread::hardware_concurrency()` workers. Albedo is `MaterialComponent::albedo` only; albedo textures and vertex colours are not sampled, so textured surfaces bounce their tint colour.
- Relocation: a probe whose rays hit backfaces more than 25% of the time is treated as buried (the DDGI paper's threshold). It steps through the nearest backface by `distance + 5%` of the allowed offset, but only if that stays within `0.45 * spacing`, and it keeps the move only if fewer rays then hit backfaces. Offsets are stored per probe. This works only for closed, consistently wound meshes.
- `engine/Gfx/EngineFrameRenderer.cpp:EngineFrameRenderer::CollectProbeBakeGeometry` — world-space triangles from visible MeshRenderers that are not `hideInGame`, have no Character or CharacterController component, and have no non-static RigidBody. Skinned meshes are skipped. Materials come from `resolveMaterialForSlot`, now a member shared with `recordMainPass` instead of a lambda. CPU triangles exist only because `AddStaticMesh` keeps `MeshGPU::cpuPositions/cpuIndices` when `m_editorOverlays` is set (the editor), so packaged games pay no memory for them.
- `.hpprobes` v1 layout (v2 adds a uint64 geometry signature after the ray count; `ReadHeader` accepts both) (`WriteProbeBake` / `ReadProbeBake` / `ReadProbeBakeHeader`): magic `HPPB`, version, centre, size, int32 counts[3], rays; then a float3 offset per probe; then 24 bytes per ray (float distance, octahedral normal as 2 x snorm16, RGBA8 albedo, float3 emissive). An 8x4x8 volume is about 0.8 MB. The reader validates the counts (1-1024) and rays (1-4096) and rejects truncated files.
- `engine/UI/QtEditor/EditorMainWindow.cpp:EditorMainWindow::bakeProbeVolumes` — runs synchronously on the UI thread with a wait cursor, for the selected volumes. The scene must be saved in a project. The file goes next to the scene as `<scene>.<tag>_<entity id>.hpprobes`, and `ProbeVolumeComponent::bakePath` stores it project-relative (serialized as `bakePath`, with an undo snapshot). `PackageStager` copies the whole `assets/` tree, so the file ships without packaging changes.
- `engine/UI/QtEditor/ProbeVolumeInspector.cpp:Refresh` — status comes from `ReadProbeBakeHeader` plus `ProbeBakeMatchesVolume`: not baked, unreadable, out of date (counts, size or centre changed), or baked. A geometry change is reported when the current `ProbeBakeGeometrySignature` differs from the one stored in the file (see below).
- `engine/Gfx/ProbeBake.cpp:ProbeBakeGeometrySignature` — the sum of a per-triangle FNV-1a hash over world positions plus material albedo and emissive. Summing makes it independent of entity iteration order, which changes when unrelated components are added or removed. It never returns 0, so 0 means "unknown": version 1 files load with signature 0, and the inspector asks for a re-bake instead of warning. `engine/UI/QtEditor/EditorMainWindow.cpp:rebuildComponentInspectors` gives `ProbeVolumeInspector::SetGeometrySignatureProvider` a lambda that runs `CollectProbeBakeGeometry` on every inspector refresh. That is proportional to the scene's static triangle count, so it shows up only while a probe volume is selected. The warning appears the next time the volume's inspector refreshes; editing other entities does not update an inspector that is already open.

## Probe GI Phase 4: GPU probe relighting

- `engine/Gfx/ProbeGI.cpp:ProbeGI::Prepare` — finds the first enabled `ProbeVolumeComponent` with a `bakePath`, resolves it against `EngineFrameRenderer::m_projectRoot` (then as given), and reloads when the path, the file's write time or the entity changes. A failed load is logged once and not retried until one of those changes. The GPU grid comes from the bake header (centre, size, counts), not the current component values, because the rays belong to that grid. Only `enabled` and `intensity` are read live. Bakes must have `kProbeBakeRaysPerProbe` (128) rays, which is the compute workgroup size. Multiple volumes are not supported yet: only the first is lit.
- `shaders/probe_update.comp` — one workgroup per probe, one invocation per ray, and every probe is updated every frame. Each ray's radiance is computed from the baked hit as `albedo / pi * (direct + bounce) + emissive`. Direct light is the sun (occlusion from the probe sun map) plus point and spot lights (unshadowed). Bounce is `sampleProbeIrradiance` from the previous frame's atlases, which gives multiple bounces over time. A ray that reached the sky uses `E_sky(dir) / pi` from the sky SH (sun excluded) when the HDRI is used for IBL, otherwise the flat ambient colour. Rays are then blended in shared memory into an 8x8 irradiance tile (cosine-weighted mean radiance, i.e. irradiance / pi) and a 16x16 visibility tile (mean distance and distance squared, cos^50 weighted, clamped to 1.5x the probe spacing). Hysteresis is 0.97, and the first frame after a load discards history. Border texels are computed directly from the direction across the octahedral fold, so no separate border pass is needed.
- Atlases (`RGBA16F` and `RG16F`, `probeCountX * probeCountY` tiles wide by `probeCountZ` tall) exist twice and alternate each frame: compute reads `[parity]` and writes `[1 - parity]`, and drawing samples `[1 - parity]`. Each swapchain image has two descriptor sets (compute and draw), rewritten in `Prepare` before recording, while that image's fence is already signalled. All atlases stay in `VK_IMAGE_LAYOUT_GENERAL`. `RecordUpdate` places a global memory barrier from earlier compute and fragment work to compute before the dispatch, and one from compute to vertex and fragment shaders after it.
- `engine/Gfx/EngineFrameRenderer.cpp:recordProbeGISunPass` — a 2048x2048 depth map over the bake's bounding sphere (radius = half the volume diagonal + max ray distance), oriented along the first shadow-casting directional light (`FindShadowCastingSun`). It draws only `IsProbeStaticMesh` geometry, the same filter the bake uses, with the CSM depth-only render pass and pipeline, plus explicit barriers (compute read to depth write before, depth write to compute read after), because that render pass's own dependencies only cover fragment-shader reads. Without a shadow-casting sun, `giParams.y = 0` and the sun is unoccluded for the probes. Note that the lighting UBO takes the last enabled directional light while the sun map uses the first shadow-casting one; they match in scenes with one sun.
- `shaders/probe_common.glsl:sampleProbeIrradiance` — DDGI-style trilinear blend of the 8 surrounding probes with a wrap-shading backface weight and a Chebyshev visibility test (cubed, floored at 0.05). Phase 5 uses the same function for surface shading. `shaders/lighting_common.glsl` now holds the lighting UBO and the light helpers previously inside `triangle.frag`, so the compute relight uses the same attenuation, spot falloff and sky SH code. The CMake shader commands depend on both include files.
- `ProbeGI::RecordDebug` — in the editor and outside Play, every probe is drawn as a sphere (generated in `shaders/probe_debug.vert`) in the scene subpass, shaded by its own irradiance for the sphere normal. Check (2026-10-28): a scratch Cornell box with 4x4x4 probes shows red on the wall-facing side of the probes beside the red wall and green beside the green wall.
- GPU time from timestamps around the sun map and dispatch: `FrameStats::probeGIGpuMs`, and logged every 600 frames as `[ProbeGI] N probes updated in X ms GPU`. Measured on Andrew's Redline bake (450 probes): about 0.11 to 0.13 ms, with one 1.1 ms reading. Timing is skipped when the graphics queue reports no timestamp bits.

## Probe GI Phase 5: surfaces lit by probes

- `shaders/triangle.frag` — when `gi.probeCounts.w == 1`, the diffuse ambient term becomes `sampleProbeIrradiance(worldPos, N) * intensity * albedo * (1 - metallic) * ao`, faded into the previous sky or flat ambient over one probe spacing outside the volume's probe bounds. Direct lighting, shadows and specular reflections are unchanged. The skinned pipeline uses the same fragment shader, so animated characters receive probe light too (they still do not block or bounce it).
- The probe set is set 2 of both surface pipelines. `VulkanPipeline::Init` takes `extraSetLayouts`, and the main layout is `[main, ProbeGI::EmptySetLayout, ProbeGI::SetLayout]`. The skinned layout is `[main, bones, ProbeGI::SetLayout]`. Set 2 is therefore not compatible between the two layouts, so `recordMainPass` rebinds `ProbeGI::DrawSet(imageIndex)` whenever the draw layout changes (`probeSetLayout`).
- Because every lit draw binds the probe set, `ProbeGI::Init` (layouts plus 1x1 placeholder atlas and buffer) and `CreateSwapchainResources` now fail `EngineFrameRenderer::Init` or swapchain recreation if they fail. The probe update pipeline, sun map, timing queries and debug pipeline stay optional. `ProbeGI::Prepare` always rewrites the image's sets: placeholders with zeroed parameters (`probeCounts.w = 0`) when no volume is loaded. `ProbeGI::Init` runs before `createPipeline` so the layouts exist. `ProbeGI::Shutdown` moved to the end of `destroyAllResources`, after the pipeline layouts that reference its set layouts.
- Check (2026-10-28): in the scratch Cornell box the floor next to the red wall reads (195,186,181) against (188,193,180) next to the green wall, and the back wall's left and right edges tint the same way. In the packaged Development build of Redline with Andrew's bake, the frame matches the old build within a few levels (the shadowed wall loses some of the flat ambient's blue). Validation shows only the existing semaphore error in both the editor and the packaged game.

## Probe GI Phase 6: hardware ray tracing toggle

- `engine/Gfx/VulkanDevice.cpp:VulkanDevice::createLogicalDevice` — when the device reports Vulkan 1.2+ and `VK_KHR_acceleration_structure`, `VK_KHR_ray_query` and `VK_KHR_deferred_host_operations`, and the `bufferDeviceAddress`, `accelerationStructure` and `rayQuery` features, it enables them through a `VkPhysicalDeviceFeatures2` chain (instead of `pEnabledFeatures`) and loads the five KHR entry points into `RayTracingFunctions`. `createAllocator` (now shared by both init paths) then sets `VMA_ALLOCATOR_CREATE_BUFFER_DEVICE_ADDRESS_BIT` with `vulkanApiVersion = 1.2`. Other GPUs create the device exactly as before. `EngineFrameRenderer::AddStaticMesh` adds device-address, storage and acceleration-structure-input usage to mesh buffers only when `SupportsRayQuery()`.
- `ProbeVolumeComponent::hardwareRayTracing` (serialized `hardwareRayTracing`, default false; inspector "Ray Tracing" group) — when set on a GPU where `ProbeGI::HardwareRayTracingAvailable()`, the volume needs no bake. `ProbeGI::createHardwareVolume` makes a GPU-only hits buffer (same `GpuRayHit` layout as an uploaded bake) and zero probe offsets, the grid follows the component and entity live, and only a probe-count change rebuilds. Without support the volume falls back to its bake, and with no bake either it is not lit. The inspector says which applies.
- `engine/Gfx/ProbeRayTracer.cpp` — one BLAS per non-skinned `MeshGPU`, built synchronously the first time an instance uses it and keyed by its vertex buffer handle. BLASes are freed only at shutdown, so a mesh reloaded under a new buffer leaves its old BLAS behind until the editor closes. Each swapchain image has its own TLAS, instance buffer, per-instance data (albedo, emissive, vertex and index buffer addresses) and scratch buffer, grown with a device wait when the instance count exceeds capacity. `Record` rebuilds the TLAS every frame (fast build, all visible non-skinned meshes including dynamic bodies, material from slot 0 only), then runs `shaders/probe_trace.comp`.
- `shaders/probe_trace.comp` — writes the same per-ray hits as the bake: geometric normal from the triangle's three vertices fetched through `GL_EXT_buffer_reference` and transformed by the instance's object-to-world inverse transpose, plus the albedo and emissive of slot 0. ## Probe GI: blotchy shading fixes (2026-10-28)

Andrew saw dark blotches on shadowed walls in Redline, both baked and traced. His volume was 100x20x100 m with 15x8x8 probes (about 7 m by 2.9 m by 14 m spacing). Three causes were fixed:
- Backface hits: `ProbeRayHit::backface` (bake: alpha byte of the stored albedo, so version 2 files keep loading; GPU: `emissive.w`; trace: from the winding of the hit triangle before the normal flip). `probe_update.comp` gives backface rays zero radiance and 0.2x distance, as in DDGI. Before this, a probe inside a wall saw the inside of the wall lit as if it were a front face and leaked that through the wall. Winding is taken as the visible side, matching `backfaceCulling`, which holds for the builtin cube (counter-clockwise from outside). Covered by `engine/Tests/ProbeBakeTests.cpp` (buried single probe and room front faces).
- Surface bias: `probe_common.glsl:sampleProbeIrradiance` takes a view direction and offsets the lookup position by `(0.2 n + 0.8 v) * 0.75 * minSpacing * 0.3`, the DDGI paper's bias, instead of `0.05 * maxSpacing` along the normal only. `triangle.frag` passes `V`, and the compute bounce passes `-dir`.
- Fixed ray directions: traced volumes rotate all 128 directions by a new uniform random rotation every frame (`ProbeGI.cpp:RandomRotation`, `ProbeGIParams::rayRotation`), shared by the trace and update passes so hits and directions agree. Hysteresis then averages over many directions. Baked volumes keep the identity rotation because their hits belong to the fixed directions.
- Density still matters: with the fixes, the coarse grid still shows faint blotches, and 40x8x40 (about 2.5 m spacing, 12,800 probes) is visibly smoother. The Cornell box values are unchanged to within one level.

## Sun shadow bias (2026-10-28)

- `shaders/triangle.frag:sampleDirectionalShadow` — the depth bias used to be `LightComponent::shadowBias` as a fraction of the cascade's NDC depth range, plus a slope term of up to 5x that, times up to 3.25x for far cascades. The cascade depth range is `max(radius, 10) + 2 * radius + 1` (`engine/Core/Math.h:ComputeCascadeShadowVP`), so the bias grew to tens of centimetres even in the nearest cascade and to metres in far ones. That lit a strip of floor along every wall base in shadow (Andrew's report). It is now sized from the cascade's texel footprint: the receiver is offset along its geometric normal by `texelWorld * (0.5 + 1.5 * (1 - N.L)) + shadowNormalBias`, and the depth bias is `(texelWorld + shadowBias) / depthRange`. `ComputeCascadeShadowVP` reports the radius and depth range through optional out parameters, and `LightingUBO` gains `cascadeTexelWorld`, `cascadeDepthRange` and `shadowBiasWorld` (appended, also in `shaders/lighting_common.glsl`).
- `LightComponent::shadowBias` and `shadowNormalBias` are now extra world-space metres on top of the automatic bias. "Normal Bias" was shown in the Light inspector and saved, but never used by the renderer before this.
- Check: in the packaged Redline start view, the bright line along the base of the right wall is gone (contrast-boosted crops). The rest of the frame is unchanged in the sampled regions.

## Sun cascade blending and fade (2026-10-28)

## Camera-following probe cascades, phase 1 (2026-10-29)

- `engine/Gfx/ProbeCascadeGrid.h`: `ProbeCascadeGrid` holds the grid maths (4 cascades, spacing 0.5 m doubling, `MinCell` centres the camera's cell, a probe's slot is its world cell modulo the grid size) and `ProbeCascadeScheduler` picks each frame's probes: probes whose cell changed (`Move`) first, finest cascade first, then the rest round-robin shared 4:3:2:1, never one probe twice in a frame (two workgroups would race on its tile). `engine/Tests/ProbeCascadeTests.cpp` covers snapping, the slot round trip, one-slab scrolling, teleports and the schedule.
- `engine/Gfx/ProbeCascades.cpp` owns one irradiance and one visibility atlas for all four cascades (tile x = slot x + slot y * count x, tile y = slot z + cascade * count z; one copy, since each probe only rewrites its own tile), a per-probe state buffer (`ivec4` world cell + update count, filled with INT_MIN = never traced), the traced rays and a 4096-probe budget (`kProbeBudget`). A grid-size change recreates everything after `vkDeviceWaitIdle`; turning cascades off (lower tiers) frees them.
- `shaders/cascade_trace.comp` traces 128 rays per scheduled probe against the scene TLAS and lights each hit itself (direct light with a traced sun ray, plus last frame's cascades at the hit, falling back to the sky), so the update pass never samples atlases it is writing. Backface hits give zero light and 0.2x distance, as in the volume. `shaders/cascade_update.comp` blends them into the probe's tiles; a probe whose stored cell differs from its slot's current cell restarts, and hysteresis ramps n/(n+1) up to 0.95.
- Probes sit at cell centres (`cascadeProbePosition`, `(cell + 0.5) * spacing`). With probes on whole-metre planes, Cornell's walls (inner faces at exactly +/-2 m) ran through probe planes, and walls were lit by probes half inside them: black walls. This is a phase 1 change from the design; phase 2 still needs relocation for walls that land near probe centres.
- GLSL `%` is undefined for negative operands, and world cells go negative: `cascadeWrap` uses floor division. With `%`, half the world sampled the wrong slots (blocky light).
- `shaders/probe_shading.glsl` now holds `skyRadiance`, `directIrradiance` (sun visibility passed in) and `texelDirection`, moved out of `shaders/probe_update.comp` unchanged so the cascade passes reuse them. `shaders/cascade_common.glsl` holds the parameters, slot maths and `sampleCascades`: the finest grid at least one probe inside its faces, cross-fading into the next over two probes; a probe counts only if its state matches its expected cell.
- `ProbeGI` creates and binds the cascades: its set gains bindings 12 to 15 (parameters, state, both atlases; placeholders when the grids do not exist), `Prepare` takes the tier's grid size and the camera, and `RecordScene` records the cascade passes after the TLAS build. `engine/Gfx/ProbeGpuUtil.h` now holds `LoadShader` and `SubmitOnce`, moved from `ProbeGI.cpp`. `EngineFrameRenderer` asks for 24 x 12 x 24 on High and 32 x 16 x 32 on Ultra when the tier ray traces.
- `shaders/triangle.frag`: the cascades replace the sky/flat ambient by their coverage weight, then a placed volume overrides them inside its box as before.

## Camera-following probe cascades, phase 2: buried probes and leaks (2026-10-29)

- `shaders/cascade_update.comp:relocate` (after RTXGI's DDGI): more than 25% backface rays means the probe is inside geometry; it moves toward the closest backface by that distance plus 0.1 spacing (half of the 0.2-spacing minimum front distance). A probe closer than 0.2 spacing to a front face moves away from it (toward the farthest front hit, or straight back from the closest). A move is kept only while the offset stays within 0.45 spacing of the cell centre. A probe still inside is switched off (`probeOffset.w = 1`) and its history is discarded. Offsets live in a new per-probe buffer (`ProbeCascades::m_offsets`, binding 19 in both the cascade compute set and `ProbeGI`'s set) and count only while `probeState` holds the same cell (`cascadeProbeOffset`); a probe that scrolls to a new cell starts at its centre.
- `shaders/cascade_trace.comp` now returns a backface hit as a negative distance instead of the 0.2x distance, so the update pass can count backfaces; the update still stores 0.2x for visibility.
- `shaders/cascade_common.glsl:sampleCascade` skips switched-off probes and uses relocated positions. Hidden probes (Chebyshev) no longer keep a 0.05 weight floor, and weights under 0.2 are crushed by w^3/0.04, as RTXGI does: with the floor, a bright probe outside a wall still contributed 5% to a dark room. Only the cascades changed; the placed-volume sampling in `shaders/probe_common.glsl` keeps its floor, which was a deliberate fix for blotchy volume shading.
- Overlay: `ProbeGI::RecordCascadeDebug` draws cascade 0 with `shaders/cascade_debug.vert/frag` (a sphere per traced probe, irradiance by direction, red when switched off) through the existing debug pipeline layout; `ProbeGI::CreateSwapchainResources` builds both debug pipelines through one lambda. `FrameRenderConfig::renderGIProbes` comes from `ViewportSettings::showGIProbes` ("GI Probes" in View > Overlays, off by default).

## Ray-traced reflections, phase 3 (2026-10-29)

- `shaders/triangle.frag:tracedReflection` (ray-query build only) shoots one ray from the surface, offset 1 cm along the geometric normal. At a triangle hit it reads the instance's albedo and emissive plus the triangle's vertices through buffer device addresses (`SceneInstances`, GI set binding 20 = `ProbeGI` `kSceneInstances`, the same `TraceInstance` data the probe tracer builds), takes the geometric normal, and lights the hit with `directIrradiance` (sun visibility traced, point and spot lights unshadowed) plus the camera-following grids' irradiance (sky outside them). - Modes come from `LightingUBO::rayReflectionParams` (appended; also in `shaders/lighting_common.glsl`): set by `EngineFrameRenderer::updateLightingUBO` to 1 (mirror, roughness < 0.3) on High and 2 (glossy, roughness < 0.6) on Ultra when the tier ray traces, else 0. Glossy rays use one GGX half-vector sample (`sampleGGX`) seeded from the world position, so the grain is fixed in place rather than flickering. The result is weighted like the HDRI reflection (Fresnel x (1 - roughness)^2 x `reflectionStrength` x AO, without the HDRI intensity).

- `shaders/probe_shading.glsl` is now included by `triangle.frag` too, and its `PI` replaced the surface shader's own. `ProbeGI`'s layout gains binding 20 only with the tracer (the last two bindings, 11 and 20, are dropped together otherwise); `prepareScene` writes it each frame beside the TLAS.

## Temporal accumulation, phase 4 (2026-10-29)

- A neighbourhood read needs the whole HDR frame, which an input attachment cannot give, so the frame is now two render passes with the same attachments, subpasses and dependencies (`VulkanSwapchain::scenePass` and `renderPass`, built by one `makePass` lambda). Being compatible, every existing pipeline built against `renderPass` (scene or overlay subpass) works in both, and no pipeline changed. `scenePass` clears and draws the scene, keeps HDR (final `SHADER_READ_ONLY`) and depth (final `DEPTH_STENCIL_READ_ONLY`) and does nothing in its second subpass; `renderPass` loads them (HDR from `TRANSFER_DST`), tone maps and draws the overlays as before. HDR gained `SAMPLED | TRANSFER_DST` usage, depth `SAMPLED`. `EngineFrameRenderer::recordMainPass` ends the scene pass where the tone map used to start, records `TemporalResolve::Record`, then begins the overlay pass.
- `engine/Gfx/TemporalResolve.cpp` + `shaders/temporal_resolve.comp`: per pixel, reproject with `previousViewProj * inverse(viewProj)` (inverse computed on the CPU, `Inverse` Gauss-Jordan) using the depth buffer, sample the previous history bilinearly, clamp it to the current 3x3 min/max, and blend 10% current. Off-screen history or a reset writes the current frame. Two GENERAL history images ping-pong; the result is copied back into the HDR image for the tone map. History resets on the first frame, swapchain recreation and a scene identity or generation change (`m_temporalScene`).
- No motion vectors: moving objects rely on the neighbourhood clamp, which limits ghosting to the colour range around each pixel. No sub-pixel jitter yet, so this is accumulation, not anti-aliasing.
