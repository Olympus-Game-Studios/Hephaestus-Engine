# Hephaestus Engine Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added
- 2026-11-13: Sketchfab and Fab plugins (**Window > Asset Stores**). Sketchfab searches downloadable models with thumbnails, author and licence (warning on NonCommercial ones), keeps your API token in Windows Credential Manager and imports a model with one click. Fab imports packs you downloaded from Fab (.zip, folder or model) and opens fab.com; it is also in the Content Browser's **Import with Plugin** menu. Both go through the new `IAssetService::ImportAssetPack` plugin service (`AssetIntake`): one prefab per model with materials made and applied (glTF and FBX materials, Megascans, Unreal and Substance texture names, packed ORM and metal/rough maps read per channel, DirectX normals flipped, LOD0 only), texture-only packs become materials, leftover textures and documents are kept, Unreal-only packs are refused with an explanation, and a `credits.json` per asset feeds a generated `assets/scripts/ImportedCredits.lua` for the game's credits.
- 2026-11-14: Asset Store Browser plugin (**Window > Asset Stores > Fab Store** and **Sketchfab Store**): each store in its own window, signed in with your own Epic account (sign-ins persist), where downloading a pack (FBX, glTF, OBJ or .zip) imports it into the open project with prefabs, materials and a credit. The plugin carries its own Qt WebEngine (about 270 MB) in its folder, so the editor itself does not; plugins can now ship their own DLLs in their bin folder.
- 2026-11-13: Models can carry default materials: a `<model>.hpmesh` settings file beside a mesh lists a material per slot, used wherever the mesh is drawn with that slot empty (editor, packaged games, thumbnails); a material set on the Mesh Renderer still wins. The Fab and Sketchfab importers write it, so dropping an imported mesh into a scene comes in textured. It moves with the model on rename, material renames update it, and the Content Browser hides it.
- 2026-11-13: Fab in the Epic Games Launcher can export straight into Hephaestus: with the launcher's export target set to Custom (socket port), Export on a listing imports it into the open project (prefabs, materials, credit) and reports the result back to the launcher. The Fab plugin listens on 127.0.0.1 on the launcher's own port, with an on/off switch, port override and credit licence in its panel.
- 2026-11-13: AI assistants can import assets over MCP: `asset.import_pack` brings in a downloaded pack (.zip, folder or model) with prefabs, materials and credits like the Fab plugin, and the Sketchfab plugin adds `sketchfab.search`, `sketchfab.import` (a background job using the saved token; NonCommercial and NoDerivs models only with `allowRestrictedLicense`) and `sketchfab.import_status`. Plugins can add their own automation tools through `IPluginContext::AutomationTools()`.
- 2026-11-13: Materials can read roughness, metallic and AO from any channel of a texture (`roughnessChannel`, `metallicChannel`, `aoChannel` in material files, scenes and prefabs), so one packed ORM map feeds all three. In the material graph, wire a Texture Sample through Break Vector (or a one-channel Component Mask) to pick the channel; materials opened in the graph editor keep theirs. The Fab and Sketchfab importers now reference packed ORM and metal/rough maps directly instead of splitting them.
- 2026-11-13: FPS plugin shotguns, loadouts and shotgun bots. Weapons can fire `pellets` in a `pelletSpread` cone, load one round at a time (`shellReload`, `shellSound`) with Fire cutting the reload short, and make a pump stroke after each shot (`cycleMotion`). `FPS.Loadout` adds a LOADOUT page (primary and secondary from the game's `LoadoutWeapons` list, with a description and damage, range, fire rate, mobility and handling bars worked out from each weapon's data) saved as `[Loadout]`; team deathmatch and waves carry only the loadout, the pause menu can change it for the next respawn, and other levels keep every weapon. `FPS.Menu` list pages take a `side` panel. A `shotgunner` bot role (`FPS.AI.Roles`) closes in at a run, holds fire at range, flanks more and prefers ground-level routes near the enemy; team deathmatch makes a quarter of its non-sniper bots shotgunners.
- 2026-11-13: FPS plugin bot roles (`FPS.AI.Roles`, the enemy's `role` variable). Snipers hang back on overwatch 20 to 50 m from the enemy, preferring cover and high ground: they hide to work the bolt and reload, peek to fire single aimed shots, move on after a few shots or when hit, fall back from anyone who gets close, and give cover fire at whoever a teammate is fighting. They see further and aim tighter, carry a visible sniper rifle (`sniperWeaponPrefab`) and do 110 damage scaled by difficulty. Team deathmatch makes about one in four of each team's bots a sniper (with three or more bots). Shots at any bot now suppress it: its aim worsens and it breaks for cover. `HeldWeapon.lua` has `stowWeapon` to put a held weapon away.
- 2026-11-13: Slide sound and dust for the player and bots (FPS plugin `slideSound`, `slideDustPrefab` and their settings, `FPS.SlideEffects`, `FPS/SlideDust.lua`). Lua `Audio.play` takes `loopStart` and `loopEnd` to repeat just part of a looping sound, `Audio.stop(h, fadeSeconds)` fades out, and `Particles.setRate` changes an emitter's rate.
- 2026-11-13: Visibility eyes in the Hierarchy and the Prefab Editor's hierarchy: click to hide or show an entity in the editor, Alt+click to isolate it; the Prefab Editor's right-click menu adds Hide, Isolate and Show All. Hiding and isolating now take an entity's children with them (isolating a weapon keeps its parts), and hidden-by-parent rows show a faded eye. Editor only: the game still sees everything, and prefabs never store it.
- 2026-11-13: Texture size limit: `Graphics.setMaxTextureSize` loads material textures at most that many pixels on their longer side, box-filtering larger ones down before upload, and reloads textures already loaded when it changes. The FPS plugin's settings have a Texture Quality choice (Low 1024, Medium 2048 by default, High full size), saved as `[Video] TextureQuality`. The editor always shows textures at full size.
- 2026-11-13: Scope lens: `Graphics.setScopeLens` draws a full-screen rifle scope in the tone map pass, with the scene seen through a barrel-distorted lens with colour fringing and darker edges, a bevelled tube, black outside and a mil-dot reticle. FPS plugin weapons take a `scope` table (magnification steps changed with the mouse wheel or the new `ZoomIn` / `ZoomOut` actions, zoomed field of view and look speed, breathing sway with hold breath on Sprint, a `4x` readout on the HUD) and a `cycleSound` for bolt actions.
- 2026-11-12: FPS plugin credits page (`FPS.Credits`): a game's credits as sections of entries (role, names, note) followed by Hephaestus Engine and the libraries in the game player, scrolling by itself and looping, with manual scrolling by keys, gamepad and wheel that stops at the first and last line, the menu tick, BACK, and UI size support.
- 2026-11-12: Team deathmatch friendly fire toggle: `Registry.matchSetup.friendlyFire` (FPS-Shooter's Versus Bots page, remembered as `[Match] FriendlyFire`, off by default). With it on, bots' stray shots now hurt teammates too, as the player's bullets and grenades already did whenever friendly fire was on.
- 2026-11-12: FPS plugin menus: items can be `disabled` (muted, not selectable to activate) and carry a `hint` shown in the hint bar, and a choice with an `action` runs it on Enter. `FPS.TeamDeathmatch` takes a one-off match setup from `Registry.matchSetup` (bot counts per team, each team's bot difficulty, score and time limits, respawn delay). Difficulty is no longer a game setting; the settings file remembers the last match (`[Match]`) and Survival (`[Survival]`) instead, and an older `[Gameplay] Difficulty` starts them.
- 2026-11-12: Bots vault and slide. The navmesh adds vault links across low cover (static boxes 0.4 to 1.1 m tall and up to 1.25 m deep with nothing over the top; `Navigation::AddVaultLinks`), paths mark them (`Nav.findPath` points with `link = true`), and FPS enemies cross them with a running jump on the hips and legs while their upper body keeps aiming; they also slide now and then on long straight runs. `Animator:SetLayer` takes a `phase`, so a one-off clip can be played on just some bones.
- 2026-11-12: FPS plugin vaulting: half walls and tables up to `vaultMaxHeight` high and `vaultMaxDepth` deep are vaulted over by jumping at them, or just by sprinting into them (`vaultWhenRunning`; never while sliding), keeping speed, with a lowered view and a slight roll. Vaults check floor and headroom at the landing and headroom over the obstacle; thin walls too tall to vault are no longer "climbed onto" into thin air. The slide legs now tuck up and flip down out of view as a slide ends (`LegsSlideExit`, `slideExitSeconds`), and the camera rises back over the same time. The legs also swing across the view and over the obstacle through a vault (`LegsVault`).
- 2026-11-11: Mesh Renderer **Draw Over World**: in play the mesh is drawn in front of world geometry like a view model, but at its own world transform and the camera's field of view, and behind view models. The FPS slide legs use it so they no longer clip into walls.
- 2026-11-11: Lua `Scene.instantiate` takes a `parent` entity option; the spawned prefab is attached to it, with `position` and `rotation` relative to it.
- 2026-11-11: FPS plugin slide camera: the player's eye eases down to `slideCameraHeight` (0.55 m) while sliding and back up afterwards, smoothly through jumps and mantles out of a slide. The slide legs now lean back with the lead leg raised so it shows while looking ahead, and sit with the hips just under the camera (`slideLegsBelowEye`) as a child of the player, so they no longer jitter against the view at high frame rates, moving back a little as the player looks down (`slideLegsPullBackAtDown`) so looking down shows your own lap without the waist cut showing.
- 2026-11-11: Mesh Renderer **Cast Shadows** (`castShadows`, on by default): off keeps a mesh out of shadow maps. FPS plugin slide legs (`slideLegsPrefab` on the Player, `FPS/SlideLegs.lua`): the player's own legs show in a slide pose while sliding, with no shadow and no collider. FPS-Shooter has a legs-only rigged mesh cut from the friendly soldier (`PlayerLegs.hpcharacter`) with LegsSlide and LegsStand pose clips.
- 2026-11-11: FPS plugin team deathmatch route points (`routePoints`, `routeChance`): soldiers with no enemy in sight sometimes head for a lane or high-ground spot first, ignoring distant gunfire on the way, so bots spread over every lane of a map instead of all taking the shortest path. FPS-Shooter has a greybox three-lane TDM map, Greybox Crossroads, now the menu's Team Deathmatch map.
- 2026-11-11: Development game runtimes built with runtime automation read `HEPHAESTUS_USER_DATA_ROOT`: when set, the game keeps its logs, saves and settings in `<root>/<game name>` instead of the player's data folder, so test packages never touch real settings. Release runtimes ignore it.
- 2026-11-11: FPS plugin menus play a tick (`Menu.tickSound`, `assets/audio/ui/tick.wav` by default, on the ui bus at `Menu.tickVolume`) each time the selection moves to another item, with the keyboard, a gamepad or the mouse, BACK and the Controls page included; not when a menu opens or refits. `tickSound` and `tickVolume` menu options override it, and `""` turns it off.
- 2026-11-11: Editor Play in New Window: the Play options menu and a new Play menu choose between playing in the viewport and in a separate, resizable game window that remembers its size and place. Escape or closing the window stops playing, and the game UI is drawn in the window as in a packaged game. Build and Run (`Ctrl+B`, the Build & Run button) packages the open scene as a Development or Release build into `Saved/BuildAndRun` without the package window and starts it, asking first when the scene has unsaved changes. Play has the `Ctrl+P` shortcut.
- 2026-11-11: FPS plugin key rebinding: Settings > Controls lists every gameplay action with two keyboard or mouse bindings and a gamepad button, rebound by pressing the new control, with swapping, clearing and Reset to defaults. Player settings and bindings are now saved as a commented, hand-editable INI file (`Saved\Config\Settings.ini` in the player's data folder, `Saved/Config/EditorSettings.ini` in the project for Editor Play), moving older saved settings across once. Every sub-menu has an on-screen BACK button, and team deathmatch shows teammates' names over their heads. New Lua APIs: `Input.getBindings`, `Input.setBindings`, `Input.getPressedControl`, `Config.load`, `Config.save`, `Config.path` and `Camera.worldToScreen`.
- 2026-11-11: FPS plugin team deathmatch with bots (`TeamDeathmatch.lua`): the player and friendly soldiers against an enemy team, a kill feed, a scoreboard on the new `Scoreboard` action (Tab), respawns away from the other team, score and time limits and a Victory, Defeat or Draw screen with Play again and Quit to menu. Enemies now fight anyone on another `team` instead of only the player, never shoot their own team, credit their kills (grenades included) and can hunt the other team when idle; the player can respawn (`respawn`) when a match brings them back. Grenades and the player's shots spare teammates while friendly fire is off.
- 2026-11-11: FPS plugin `HeldWeapon.lua` can point a held weapon where its character faces (`alongFacing`, `forwardYawDegrees`) and shift it sideways (`gripSide`). Enemies now hold their rifle straight ahead in the right hand with the handguard at the left hand, further forward than before, instead of along the line between the hands, which swung across the body between clips.
- 2026-11-11: FPS plugin combat readability: enemy muzzle flashes at the rifle's muzzle, tracers for the player's and enemies' shots that fly the shot's real path, and a red arrow round the crosshair pointing to where damage came from. Smoke grenade clouds now block enemies' sight, and on higher difficulties enemies fire blind into the smoke where they last saw the player.
- 2026-11-11: Editor viewport icons for particle emitters, audio sources, trigger volumes, the Environment, probe volumes and script-only objects, beside the light icons, and every camera now shows the built-in camera model aimed where it looks, with a faint view outline. All are editor-only and clickable. The FPS plugin's menus only react to the mouse over an item itself, not anywhere along its row, and their highlight now slides between items (Settings > Reduce Motion turns that off). The in-game menu no longer pauses the game (ready for multiplayer); the player just stops responding while it is open, with `pauseFreezesTime` to freeze it instead and `pauseMenuRestart` to hide Restart. F1 also opens and closes it (Escape stops Editor Play). Menu labels are centred in their highlight.
- 2026-11-11: Lua `UI.measureText(text, size, bold, family)` gives the width game UI text will take. In Editor Play, UI text now uses the same font file and size as the packaged game (it was drawn larger, in points, from a different font). FPS menu labels share one left edge with their title (and the main menu's wordmark), each highlight wraps its label with equal padding measured from the drawn text, and the main menu is 1.3 times the size of the in-game menu.
- 2026-11-11: Single-line UI text is centred on its capital letters instead of its whole line box, in the editor and in games, so labels no longer sit low in buttons and bars.
- 2026-11-10: Lua `Animator:SetTime(seconds)` jumps the current animation to a time, so characters playing the same loop can be started out of step.
- 2026-11-10: Bloom on the Environment (intensity, threshold and radius): bright areas glow into their surroundings, in the editor and in packaged games. Scenes without bloom render exactly as before.
- 2026-11-10: Post processing on the Environment: exposure, contrast, saturation, a colour filter, vignette, film grain and scanlines, applied to the whole picture in the editor and in packaged games (game UI is drawn on top, untouched). Set them in the Environment inspector; scenes saved before keep their look.
- 2026-11-10: FPS plugin menus: Escape (gamepad Start) pauses the game with Resume, Settings, Restart, Quit to menu and Quit game. Settings has look sensitivity, field of view, view bob, camera shake, volume for each sound group and difficulty, and is saved for next time. `FPS.Menu` builds the same style of menu from a script, for a main menu or anything else, and works with the keyboard, the mouse and a gamepad. FPS-Shooter has a main menu scene that starts the Survival level.

- 2026-11-10: Lua `Scene.load(path)` switches to another scene at the next safe point, in Editor Play and packaged games; stopping Play returns to the edited scene. `Time.setScale` slows, speeds up or freezes gameplay (scripts, physics, animation and particles; not sound or UI), with `Time.getScale` and `Time.unscaledDeltaTime`. `Storage.save(name, table)` and `Storage.load(name)` keep data such as settings in the player's own data folder.
- 2026-11-10: FPS plugin waves and restarts: `WaveDirector.lua` spawns waves of enemies that hunt the player, with a per-wave difficulty, wave and "cleared" messages and a win when the last wave is cleared. Dying or winning shows a message and offers a restart (`Scene.reload`). FPS-Shooter has a Survival level that uses it.
- 2026-11-10: FPS plugin enemy bodies stay in the level until more than `maxCorpses` (8) lie there, then the oldest is removed with its dropped weapon; they no longer disappear after a set time unless `corpseSeconds` is set.
- 2026-11-10: FPS plugin grenade warning: a HUD icon circles the crosshair towards each live frag near the player, with an arrow pointing at it, white when it is near, orange when its blast would hurt and red when it would kill (`grenadeWarningIcon`, `grenadeWarningArrowPattern` and related player settings).
- 2026-11-10: Ragdolls: Lua `Character.ragdoll(impulse, point)` turns a humanoid Character (Mixamo bone names) into 11 jointed capsules that fall under physics and drive its bones, replacing its Character Controller and the colliders of its children; hits on the ragdoll report the character. `Character.isRagdoll()` says whether it has. FPS plugin enemies ragdoll on death, pushed away from the shot or the blast, and drop their rifle (`HeldWeapon.lua` `dropPrefab`).
- 2026-11-10: Navigation: a navmesh built with Recast & Detour from a scene's static box colliders the first time a script needs it in Play, and the Lua `Nav` table (`isReady`, `rebuild`, `findPath`, `closestPoint`, `randomPoint`). Lua `e:GetParent()` returns an entity's parent. A Character Controller no longer collides with bodies parented under its own entity, such as an enemy's hit zones.
- 2026-11-10: FPS plugin enemies: `Enemy.lua` patrols, notices the player by sight and sound, fights in bursts with aim that settles over time, takes cover and peeks out, searches where it last saw the player, runs from live frags, warns nearby allies and dies into a corpse. How well enemies fight comes from difficulty presets (`recruit`, `regular`, `hardened`, `veteran`) that a settings menu can switch or override per value, and each enemy can use its own level or values. Behaviour is built from reusable modules (`FPS.AI.Brain`, `Perception`, `Mover`, `Cover`, `Tactics`, `Difficulty`). Enemies throw frags at a hidden player and go round their cover, with their own difficulty values, and hold a rifle through `HeldWeapon.lua`, which keeps a weapon mesh between a character's hand sockets. A hit zone with no `owner` belongs to its parent. See the FPS plugin documentation.
- 2026-11-10: FPS plugin shell casings: weapons eject a `casingPrefab` on every shot that tumbles, bounces and settles, cleaned up after a few seconds and capped per weapon.
- 2026-11-10: FPS plugin bullet travel: weapons with a `muzzleVelocity` fire bullets with flight time and drop, checked along their path each frame, so close shots still land at once.
- 2026-11-10: FPS plugin lean: hold `LeanLeft` (C) or `LeanRight` (V) to move the view and aim sideways with a camera roll, stopping short of walls.
- 2026-11-10: Character Controller **Prone Height** and Lua `Character.setProne` / `Character.isProne`: a third, shortest stance whose capsule only gets up when the taller one fits. The FPS plugin's `Prone` action (X, right stick press) lies down, crawling slowly with a low view, less spread and less recoil.
- 2026-11-10: Character Controller **Coyote Time** (a jump still works briefly after walking off a ledge) and **Jump Buffer** (a jump pressed just before landing happens on landing), both off by default. FPS plugin tactical sprint: double-tap Sprint for a faster, limited sprint with the weapon carried barrel-up and a longer sprint-to-fire time. FPS plugin mantle and vault: jumping at a ledge climbs onto it, or vaults over a low, thin obstacle, with the weapon lowered. FPS plugin slide: crouch while sprinting to slide, with a speed burst that eases to crouch speed, slow steering, camera tilt and wider field of view, and a jump that cancels it while keeping momentum. FPS plugin movement feel: slower strafing, backpedalling and crouch-walking, a short slowdown after hard landings, and 0.12 s of coyote time and jump buffering on the FPS player.
- 2026-11-10: FPS plugin grenades: hold `ThrowFrag` (G) or `ThrowSmoke` (T) to aim with a trajectory arc, bounce markers and a marker where it will end up, and let go to throw the player's `fragGrenadePrefab` and `smokeGrenadePrefab` with a weapon dip and optional arm and throw sounds (`grenadeArmSound`, `grenadeThrowSound`), and the HUD shows how many are left. `Grenade.lua` gives a prefab a fuse: a frag spawns its explosion effect and sound, damages everything with health in its radius that is not behind cover (full damage inside an inner radius, falling off to the edge) and shakes the camera; a smoke grenade spawns its cloud and removes itself later. Lua `t:GetWorldPosition()` reads any entity's position in the world.
- 2026-11-10: Particle Emitter component: camera-facing particles with rate and burst emission, looping or one-shot (optionally removing the entity when done), lifetime, speed, spread cone, gravity, drag, size, colour and fade over life, spin and a seed, drawn with an alpha-blended or additive material. Saved in scenes and prefabs, edited in the Inspector, and controlled from Lua with `Particles.play`, `stop`, `burst`, `isPlaying` and `count`. The FPS plugin uses it for impact dust, sparks off targets and muzzle smoke (`impactDustPrefab`, `impactSparksPrefab`, `muzzleSmokePrefab`).
- 2026-11-10: Materials can be alpha-blended or additive (`"blendMode": "alphaBlend"` or `"additive"` in a `.hematerial`). Blended surfaces use the albedo texture's alpha, are drawn after solid surfaces from furthest to nearest and cast no shadows; additive ones are unlit and glow. The FPS plugin uses them for muzzle flashes (`<Weapon>_Flash_*` quads with `MuzzleFlash.lua`) and bullet hole decals (`impactDecalPrefabs` on the player).
- 2026-11-10: New audio engine built on miniaudio 0.11.26: any number of sounds mix at once (up to a 48 voice budget, with priorities deciding which sound is replaced when it is full), files are decoded once and kept in memory, buses (`master`, `sfx`, `weapons`, `music`, `ui`) have their own volumes, every play can vary its pitch and volume, and 3D sounds get quieter with distance and pan to the side they come from, heard from the active camera. FLAC plays as well as WAV and MP3. Audio Sources have **Bus**, **3D**, **Min Distance** and **Max Distance**. Lua `Audio.play` takes an options table, and there are `Audio.setPitch`, `setPosition`, `setBusVolume`, `getBusVolume` and `getVoiceCount`. The FPS plugin plays weapon sounds on the `weapons` bus with per-shot variation and layered shots (`fireLayers`), and footsteps with variation. Automation tool `audio.get_status` reports voices, cached sounds and bus volumes. See [audio.md](docs/user-guide/audio.md).
- 2026-11-10: FPS plugin gunplay feel: weapons can read their tuning from a data file (`definition`); recoil and spread are seeded so a string always kicks the same way; weapon kick uses exact damped springs with kick given as peak movement, plus side kick and a separate camera kick that never moves the aim; the weapon trails how fast you turn, breathes and drifts at idle, trails movement, rolls into strafes and dips on landings and footsteps; ADS zoom and look speed follow their own curve; a trigger press just before sprint-to-fire ends is kept; reloads are timed magazine events with a chambered round (30+1 tactical reloads, ammo moves when the magazine goes in) and stop cleanly when you sprint or switch; `viewBobScale` and `cameraShakeScale` turn down motion without changing gameplay. See the FPS plugin documentation.
- 2026-11-09: Automation tool `prefab.create` saves an entity and its children as a `.hpprefab` under the project's assets and replaces them with an instance, like Create Prefab From Selection.
- 2026-11-09: FPS plugin `Weapon.lua` `sightPitch` and `sightYaw` tilt the weapon in ADS so iron sights whose line is not parallel to the barrel still line up on the screen centre. See the FPS plugin documentation.
- 2026-11-09: Camera **View Model FOV** (`viewModelFov`): First-Person View Model meshes are drawn with their own field of view, so ADS zoom changes the world but not the size of the weapon. 0 keeps the camera's field of view.
- 2026-11-09: Importing a character from FBX brings its materials: each material slot gets a material with the FBX base colour, roughness and metalness, and its base colour and normal textures are extracted into the character's folder, so Mixamo characters no longer import white.
- 2026-11-09: FPS plugin gunplay: ADS that zooms the camera and blends the weapon to its sight, recoil that moves the real aim along a learnable per-weapon pattern with recovery, spring-driven visual kick, sway, walk bob and sprint lowering, a hip spread cone that grows with movement and fire, damage falloff with range, head and limb hit zones (`HitZone.lua`), hit and kill markers, tactical and empty reloads with timed sound cues, sprint-to-fire delay and weapon raise and lower times. Every value is a `Weapon.lua` variable. See the FPS plugin documentation.
- 2026-11-09: Mesh Renderer **First-Person View Model**: in play the mesh is drawn attached to the active camera, in front of all world geometry, and casts no shadows, so weapons never clip into walls.
- 2026-11-09: Lua `entity:GetId()` returns a stable integer id. `Physics.raycast` hits report `sensor`, and its tenth argument can be a list of entities to ignore.
- 2026-11-09: Automation tool `character.import_clips` imports animation clips from a GLB or FBX into an existing character.
- 2026-11-06: New projects open to a lit scene instead of a black one: `default.hpscene` has an Environment using the starter HDRI (a solid sky colour if the HDRI couldn't be copied), a directional sun, a static floor plane with a box collider and an active camera. The project's Default Skybox is set to the starter HDRI.
- 2026-11-06: The editor reimports meshes, textures and sounds when their source files change on disk, and the Content Browser refreshes when files in the asset root or the open folder are added, removed or edited. Restore Deleted Asset on the Content Browser's empty-area menu lists the project trash and puts the chosen asset back where it was.
- 2026-11-06: Gamepads work in Editor Play on Windows, through the same GLFW polling the packaged game uses. macOS Editor Play stays keyboard and mouse only, because GLFW's macOS setup takes over the application delegate Qt relies on.
- 2026-11-06: Engine Settings > Gizmo Size scales the viewport gizmo, Project Settings > Physics Enabled turns physics off in Editor Play and in packaged games (`physics_enabled` in `game.ini`) and Project Settings > Default Skybox gives File > New Level an Environment with that HDRI; its browse button picks an HDR or EXR file. A Mesh Collider's Debug Draw Bounds draws its bounds as a green box in the viewport.
- 2026-11-04: The launcher has its own icon (an orange tile with the Hephaestus H) on Windows: the .exe in Explorer, the window title bar and the taskbar. The editor keeps its icon. On macOS the launcher .app still uses the shared app icon.
- 2026-11-04: Projects record the newest engine version that has opened them. When the editor opens a project, it writes its own version to `engineVersion` in `project.heproject` unless a newer Hephaestus has already opened the project; then it leaves the version alone and warns, before the project opens, that it may use features this version doesn't support and that saving could lose that work. See [ProjectFormat.md](Documentation/ProjectFormat.md#engine-versions).
- 2026-11-04: `THIRD_PARTY_NOTICES.md` lists every third-party component shipped in the editor, launcher and packaged games (Qt with the LGPLv3 and GPLv3 texts, where to get its source and the notices for the third-party code inside Qt, Lua, Vulkan Memory Allocator, Jolt, EnTT, GLFW, nlohmann/json, cpp-httplib, ufbx, stb, the Inter, JetBrains Mono, Font Awesome and Roboto fonts, Material Icon Theme, and MoltenVK and the Vulkan loader on macOS) with their full licence texts. It is installed beside the editor, included by both release package scripts, and copied into every packaged game as `ThirdPartyNotices.txt`, replacing the partial notices built from `extern/` (which a Steam install doesn't have) and the "licence review required" packaging warning. The About window's Credits page links to it and now lists MoltenVK.
- 2026-11-04: The editor status bar shows the editor's RAM, CPU and GPU usage in every mode, updated once a second. Each readout can be turned off from the status bar's right-click menu or View > Status Bar, and the choice is remembered. GPU usage needs Windows; on other platforms the toggle is disabled.
- 2026-11-04: Content Browser cards show previews: textures show the image itself, materials are rendered on a sphere, and meshes and prefabs are rendered from a three-quarter view with their materials. #### Multi-Selection Support in Outliner (2026-01-29)

**Feature**: Users can now select multiple actors in the World Outliner and viewport using 
standard multi-selection controls. This enables batch operations on multiple entities.

**Key Features**:

1. **Ctrl+Click (Cmd+Click on macOS)**: Toggle individual selection - add or remove an 
   entity from the current selection without affecting other selected entities.

2. **Shift+Click**: Range selection in the Outliner - select all entities between the 
   last clicked entity and the current entity in the visible tree order.

3. **Viewport Multi-Selection**: Ctrl+Click on objects in the 3D viewport to add/remove 
   them from the selection.

4. **Synchronized Selection**: Selection state is synchronized between the Outliner, 
   viewport, and Details panel. All selected entities show selection outlines.

5. **Multi-Entity Transform Editing**: When multiple entities are selected, transform 
   changes in the Details panel (position, rotation, scale) apply to all selected entities.

6. **Gizmo Multi-Transform**: Using the viewport gizmo to move/rotate/scale affects all 
   selected entities simultaneously, maintaining their relative positions.

**Changes Made**:

1. **HtmlEditorUIHost.cpp**:
   - Added `scene.range_select` handler for Shift+Click range selection
   - Handles comma-separated entity IDs for batch selection

2. **outliner.html**:
   - Added tracking of visible entity order for range selection
   - Implemented Shift+Click range selection logic
   - Enhanced Ctrl+Click to properly toggle selection
   - Updated status bar to show selection feedback

3. **main.cpp**:
   - Viewport picking now supports Ctrl+Click for multi-selection toggle
   - Gizmo transformations apply to all selected entities using delta transformation
   - Selection outline rendering updated to draw outlines for all selected entities
   - ImGui WorldOutliner updated with Ctrl+Click support

4. **Scene.cpp** (existing infrastructure):
   - `GetSelectedEntities()` returns all selected entities
   - `AddSelectedEntity()` adds to multi-selection
   - `ToggleSelectedEntity()` toggles individual selection
   - `ClearSelection()` clears all selections

**Backward Compatibility**: Single-selection behavior remains unchanged. Clicking without 
modifiers still replaces the current selection with the clicked entity.

#### Multi-Material Mesh Rendering in Game Runtime (2026-01-28)

**Problem**: Meshes with multiple material indices (multiple submeshes/sections) were not 
rendering correctly in the exported/standalone game runtime. Only the first material would 
show, or sections would fallback to a default material, even though they rendered correctly 
in the editor.

**Root Cause**: 
1. When loading meshes at runtime, the `MeshRendererComponent::submeshCount` was not being 
   updated from the loaded mesh data, causing a mismatch between the mesh's actual submesh 
   count and the component's tracked count.
2. The runtime was properly storing submesh data in `MeshGPU::submeshes` but the renderer 
   component wasn't synchronized.

**Changes Made**:

1. **GameMain.cpp - Mesh Loading** (`LoadMeshToGPU` integration):
   - After loading a mesh from file, now properly updates `renderer.submeshCount` from the 
     loaded `MeshGPU::submeshes` array.
   - Added debug logging showing mesh name, submesh count, and material slot count.
   - Added warning when submesh count doesn't match material slot count.
   - Same synchronization added for cached mesh reuse path.

2. **GameMain.cpp - Debug Logging** (Debug builds only):
   - Added comprehensive multi-material debug info section before the main render loop.
   - Logs each entity's mesh name, handle, submesh count, and material slot count.
   - For each submesh, logs the material slot index, index range, material path, and 
     whether the material was successfully loaded.
   - Warns when there are more submeshes than material slots.

3. **GameMain.cpp - Runtime Asset Path Resolution**:
    - `NormalizeAssetPath()` now resolves relative material/texture paths under 
       the runtime `assets/` directory if the direct runtime-root path doesn't exist.
    - Fixes cases where editor-stored paths like `materials/rock.hpmat` were 
       not found at runtime (expected under `assets/materials/...`).

4. **SceneExporter.cpp - Export Material Slot Assets**:
    - Export now includes material assets referenced by mesh slot overrides
       (`MeshRendererComponent::appliedMaterialPaths`), ensuring they are copied
       into the runtime `assets/` folder.

5. **GameMain.cpp - World-Aligned Material Graph Support (Runtime)**:
    - Runtime material loader now detects `WorldAlignedTexture` nodes in the
       material graph and enables world-aligned UVs, texture binding, and
       world texture scale without requiring the editor-side graph evaluator.

3. **Test Scene**:
   - Added `assets/scenes/MultiMaterialRuntimeTest.hpscene` to test:
     - Single material meshes (should render normally)
     - Override material tests (material should apply correctly)
     - Missing/fallback material tests (should use entity's MaterialComponent)

**New Debug Warnings** (in debug builds):
- "Mesh 'X' has N submeshes but M material paths assigned. Some sections may use fallback materials."
- Per-submesh material resolution status: "loaded", "NOT FOUND", "default", or "slot missing"

**Acceptance Criteria**:
1. ✅ Multi-material meshes render identically in editor and runtime
2. ✅ Each submesh uses its assigned material slot
3. ✅ If a material slot is missing, only that section falls back to default
4. ✅ Blueprint/scene overrides for per-slot materials work in runtime
5. ✅ Single-material meshes continue to work without regression
