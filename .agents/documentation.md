# Documentation

- Update relevant user/developer documentation when public behavior, setup, or workflows change. Document new public APIs and significant architecture decisions.
- Verify documentation against current source, tests, and configured behavior. Clearly distinguish implemented behavior from proposals, plans, and unverified paths.
- Preserve the repository's existing documentation layout and conventions; update the relevant existing guide rather than creating parallel documentation without a reason.
- Keep comments focused on intent and non-obvious decisions. Do not narrate code line by line or document behavior that is not implemented.
- For release-note requirements, read `.agents/changelog.md` before editing `CHANGELOG.md`.
